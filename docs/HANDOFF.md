## What this is

**take the crown** ($CROWN): one crown that earns 85% of a pump.fun coin's creator fees (15% to the dev wallet). Anyone can take it by paying its price; 90% goes to the old king, 10% is burned. The price jumps 1.3 to 1.6x on a takeover and melts 2 to 8% a minute, down to a floor of 10 minutes of fees.

## Keys and test SOL: these do not survive a new session

The work so far ran in a temporary cloud machine. Two devnet keypairs live only there and are **not in the repo** (by rule):

- `~/.config/solana/devnet.json`, address `7asfvZur2Tmu2mDDeRheobT3vs7ZRWCjwEWr8DVrXN6u`: upgrade authority of the devnet program, creator of the test coin, authority of its unlocked crown config. Holds about 3 devnet SOL.
- `~/.config/solana/crank-devnet.json`: small crank key, about 0.15 devnet SOL.

A new session starts without them. That is acceptable (devnet only), but it means:

- The devnet program can no longer be upgraded and the test coin's config can no longer be changed. To change either, generate a new key, get devnet SOL from faucet.solana.com (the faucet rate-limits cloud machines, so the owner has to request it), deploy the program under a **new program id** (update `declare_id!`, `Anchor.toml`, `pnpm build:program`), run `scripts/devnet-launch.ts`, and set `MINT` on Vercel.
- The current test coin keeps working on the site as it is: taking the crown needs no special key.
- The devnet program has the old 10% cap on the in-program dev fee. It only matters for the fallback fee path, which the site does not use.
- The devnet program also predates the floor cap (`docs/SECURITY-REVIEW.md` F1, fixed in the code 2026-11-12). Redeploy under a new program id before testing on devnet again.

## Setting up a fresh machine

Not installed by default; all of it is needed only for program work, not for website changes.

- Solana CLI 2.3.13: download `https://release.anza.xyz/v2.3.13/solana-release-x86_64-unknown-linux-gnu.tar.bz2`, extract, add `solana-release/bin` to `PATH`. (Piping the install script to a shell is blocked in these sessions; the tarball is fine.)
- Anchor CLI 0.32.1: `apt-get install -y libudev-dev pkg-config`, then `cargo install anchor-cli --version 0.32.1 --locked` (about 10 minutes).
- `pnpm install`, then `pnpm build:program` before `pnpm test`.
- Website only: `pnpm install`, `pnpm typecheck`, `pnpm --filter app test`, `pnpm app:smoke`.

## Things that have bitten already

All are in `CLAUDE.md` under Toolchain; the short version:

- Vercel refuses `require()` of ES modules. Check API-route dependency changes with `NODE_OPTIONS=--no-experimental-require-module` before merging. A miss here took the live API down for half an hour once.
- The public devnet RPC rate-limits hard (429). Scripts throttle themselves; the live site will struggle with more than a few visitors until it has a paid RPC.
- `litesvm` crashes Node after a failed transaction; tests use `solana-bankrun`.
- The browser must never import the SDK's index (it drags in pump.fun's SDK); only `@koth-crown/sdk/src/math`.
